# K 线回放交易设计

## 目标

在现有 K 线回放中加入可重复验证的模拟交易，并保持叠加标的同步回放。功能只做历史数据演练，不发出真实交易指令，也不写入 QMT。

## 模块边界

### 1. 回放事件

- `bar-replay-start`：发布完整历史序列、起点和当前 K 线。
- `bar-replay-cursor`：每次单步或播放推进后发布游标和当前 K 线。
- `bar-replay-status`：发布播放、暂停状态。
- `bar-replay-exit`：退出前发布最终快照，随后恢复完整图表。
- 事件同时支持内部订阅和浏览器 `CustomEvent`，但同一消费者只订阅一种通道，避免重复处理。

### 2. 交易引擎

- 单标的、单持仓、纯内存状态机。
- 买入金额换算持仓数量：`数量 = 买入金额 / 买入价格`。
- 浮动盈亏使用当前回放 K 线收盘价：`盈亏金额 = (当前收盘价 - 买入价) * 数量`。
- 盈亏百分比：`盈亏金额 / 买入金额 * 100%`。
- 手动买卖可选择开盘、最高、最低、收盘四种价格要素。
- 手动卖出必须位于买入 K 线之后，防止同一根 K 线利用事后高低点完成不真实成交。
- 预设价格在 `low <= target <= high` 时触发；同一根 K 线触发买入后不得再触发卖出。
- 第一阶段不计算手续费、滑点、整手限制和分红复权差异。

### 3. 图表交互

- 回放开启后显示“买入、卖出、预设、交易记录”。
- 点击买入或卖出后，再点击当前可见 K 线，选择该 K 线的价格要素。
- 买入金额默认 100000，可在执行前修改。
- 买卖点、预设水平线、浮动或已实现盈亏显示在独立 SVG 层，不修改主 K 线数据。
- 买入使用蓝色、卖出使用紫色，避免与主图红涨绿跌混淆。
- 浅色和深色主题分别保证文字、面板和标记对比度。

### 4. 叠加同步

- 回放开始时，叠加模块保留完整回放历史。
- 游标推进时只在本地裁切主图和叠加数据，不重新请求网络。
- 回放中新增叠加标的时，请求完整回放时间窗，然后随游标同步推进。
- 退出回放后恢复原有可见窗口和叠加计算。

## 关键状态

- `position`：当前持仓及入场信息。
- `pendingOrders.buy/sell`：预设买卖价。
- `completedTrades`：已完成交易。
- `realizedPnl`：已实现盈亏。
- `unrealizedPnl`：按当前回放收盘价计算的浮动盈亏。

## 验收标准

1. 回放、叠加可同时使用，单步时两者同步且不重复请求叠加行情。
2. 四种 OHLC 价格均可作为手动买入和卖出价格。
3. 买入后每推进一根 K 线，浮亏或浮盈金额和百分比按该 K 线收盘价更新。
4. 预设价只有进入 K 线高低区间才成交，同一 K 线不会同时买入卖出。
5. 卖出后显示买卖价格、盈亏金额和盈亏百分比。
6. 退出回放清空本次模拟交易状态，不影响真实行情和图表上下文。
7. 新模块通过语法检查、Node 单元测试、前端入口契约、完整 pytest 和真实浏览器交互验收。

## 后续可扩展项

- 手续费、滑点、A 股整手和涨跌停成交约束。
- 多笔加仓、部分卖出和资金曲线。
- 回放方案保存、导出与复盘会话关联。
- 复权口径选择和除权除息处理。
