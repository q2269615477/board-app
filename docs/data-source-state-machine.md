# board-app 数据源与更新时间状态机

本文记录面板当前各功能区在盘中、午休、盘后所使用的数据源、刷新频率、持久化边界和失败降级规则。它也是后续模型修改数据链路时必须遵守的契约。

## 一、数据源职责

| 数据 | 主数据源 | 降级来源 | 是否写入 SQLite |
| --- | --- | --- | --- |
| A 股个股、指数实时 OHLC | QMT HTTP `127.0.0.1:18080/ohlc_batch` | 本地最近结算日线 | 否 |
| A 股个股、指数分钟 K | QMT HTTP `18080/candles` | 仅在 xtdata 行情服务确实可用时降级 | 否 |
| A 股个股、指数历史日 K | SQLite | `18080/candles`、QMT 公式口、QMT 本地 datadir | 通过校验后写入 |
| 行业、概念板块盘中快照 | 东财 `push2delay` 全量分页 | 最近一次有效快照 | 仅内存 |
| 行业、概念板块正式日 K | Tushare `dc_daily` | 东财历史接口作为临时候选 | 目标交易日校验后写入 |
| 行业、概念板块成分 | 本地 `industry_constituents.json`、`concept_constituents.json` | 最近一次有效本地快照 | 离线任务更新 |
| 国内指数成分 | SQLite `index_constituents` | 最近一次有效快照 | Tushare `index_weight` 离线更新 |
| 成分股实时价格 | QMT HTTP `18080/ohlc_batch` | SQLite 最近两根日 K | 不写实时数据 |
| 港股、美股、亚太指数 | 腾讯，失败后新浪 | 最近缓存 | 否 |

QMT 18080 只负责沪、深、北国内股票和指数。港股、美股、亚太指数不得伪装成国内代码发送给 18080。

这里要区分三层：

1. **交互层**：浏览器点击和盘中跳动只读 SQLite + 18080，追求瞬时响应，不写正式日线。
2. **结算层**：15:30 后国内个股由 18080 `ohlc_batch` 按 80 只一批写目标日 bar，指数由独立的 QMT 公式口 `58600`/本地数据更新；17:00 后由 Tushare 结算东财板块。`18080` 和 `58600` 必须分别探活，任何一方故障都不能跳过另一方仍可执行的结算。
3. **维护层**：每天按游标抽取一小批国内标的，用 18080 全历史与本地日线合并校验，修复早年截断或内部缺口。

Tushare 对国内指数存在一个**盘后尾部安全兜底**：只有 QMT 指数日线明显滞后时才允许补齐历史尾部。它不参与分钟线、盘中跳动或个股盘后日更。

## 二、功能区数据链路

### 1. 顶部指数栏

前端以 HTTP 首屏和 WebSocket 增量消息更新 `/api/spot/indices`。每个标的按交易所本地时钟独立判断是否实时刷新；午休、收盘和周末只展示最后有效缓存或 SQLite 快照，不访问外部实时源，也不触发价格闪动。`zoneinfo` 负责时区换算及美国夏令时，禁止硬编码北京时间偏移。

| 市场 | 时区 | 工作日实时窗口 |
| --- | --- | --- |
| A 股、东财、微盘 | `Asia/Shanghai` | 09:15-11:30、13:00-15:00 |
| 恒生指数、恒生科技 | `Asia/Hong_Kong` | 09:30-12:00、13:00-16:10 |
| 日经 225 | `Asia/Tokyo` | 09:00-11:30、12:30-15:30 |
| KOSPI | `Asia/Seoul` | 09:00-15:30 |
| 台湾加权 | `Asia/Taipei` | 09:00-13:30 |
| 标普、纳指、道指 | `America/New_York` | 09:30-16:00 |

所有区间均采用左闭右开边界；未知代码保守视为静态、休市。任一市场开市时顶部行情使用短 TTL；全部市场休市时使用长 TTL。市场阶段签名变化会立即触发一次刷新和广播，即使价格本身没有变化。

- 上证、深证、科创、沪深300等国内指数：由 `nav_spot_service` 批量请求 18080。
- 顶部包含的个股：同样走 18080。
- 东财板块类指数：走板块快照缓存。
- 港股、美股、亚太指数：腾讯优先，新浪降级。
- 页面显示格式为“涨跌幅（现价）”。
- 18080 不可用时允许显示最近有效值，但必须保留来源信息，不能把旧值标成实时值。

### 2. 左侧分类和板块涨跌幅

分类树本身来自 `static/board_classification.json`，启动后一次加载，共包含行业、概念、指数三种类型。文件是“分类 -> 子分类 -> 板块”的嵌套结构，读取方必须递归展开；当前共 1128 项，其中行业 497、概念 493、指数 138。

板块涨跌幅来自 `/api/board-changes`：

- 09:15-11:30：东财 `push2delay` 全量分页快照。
- 11:30-13:00：使用上午最后快照，禁止重新访问东财。
- 13:00-15:05：恢复东财全量快照。
- 15:05-17:00：保留东财收盘候选，不尝试用尚未发布的 Tushare 板块日线覆盖。
- 17:00 后：Tushare 当日数据可用后替换为正式结算值。
- 服务端盘中缓存 TTL 30 秒，盘后 TTL 5 分钟。
- 前端兜底轮询：交易时段 60 秒，非交易时段 5 分钟；SSE/实时事件可提前触发局部更新。

东财接口单页最多返回约 100 条，必须依据返回的 `total` 动态翻页。禁止恢复固定 5 页或 6 页的旧写法。

### 3. 左侧板块和指数成分股

点击行业、概念时：

- 成分关系只读本地 JSON 内存缓存，不在点击时调用 Tushare。
- 默认价格、涨跌幅读取 SQLite 最近两根已结算日 K。
- 前端成分列表盘中缓存 10 秒，非盘中缓存 60 秒。
- 用户点击刷新按钮时，后端用 18080 补充市值靠前的 80 只成分实时 OHLC；其余成分继续显示 SQLite 结算值，避免大批量请求阻塞当前图表；实时值不写入 SQLite。

点击指数时：

- 类型必须保持 `index`，不得转换成 `concept`。
- 成分关系读取 SQLite `index_constituents` 最新快照。
- 快照由 `scripts/update_index_constituents.py` 在离线更新阶段调用 Tushare `index_weight` 生成。
- 当前本地已为分类文件中的 138 个指数生成快照，共约 3.8 万条成分关系。
- 点击过程不访问 Tushare，因此应为瞬时响应。

### 4. 中央 K 线图

点击标的后先请求：

`/api/kline/<type>/<code>?period=<period>&cache_first=1`

行为如下：

1. 浏览器短期缓存命中时直接绘图。
2. 否则优先返回 SQLite 历史数据，并在后台刷新。
3. 缓存优先响应不得等待外部行情接口。
4. 国内个股、指数日线加载完成后，可附加 18080 当日临时 OHLC 覆盖。
5. 连续交易时图表订阅每 3 秒请求一次 `/api/spot/...`，只更新当前最后一根 bar；国内标的在午休、盘后和周末每个阶段只读取一次固定值。
6. 临时 OHLC 绝不作为正式日线写入 SQLite。

分钟周期：

- `1m` 从 18080 取明确数量的分钟 bar。
- `5m/15m/30m/60m/120m/240m` 优先由 1 分钟数据按 A 股上午、下午交易时段重采样。
- 120 分钟和 240 分钟不能跨午休错误拼接。
- 18080 的 `count=-1` 会返回空数据，禁止再把 `-1` 当作“全部”。

周、月、季、年周期：

- 唯一真源是已验收的日线。
- 每次受影响的周期必须从完整日线重算。
- 写库时在同一事务中删除旧周期、写入新周期并更新元数据。
- 不能只比较“最后日期相同”就复用旧周线或月线，因为同一交易日内 OHLC 仍可能变化。

### 5. 右侧会话、标注、支撑位和共振

这些功能使用本地会话、标注、关系和案例存储，不依赖盘中行情接口。只有在读取当前图表、K 线或成分价格时，才间接使用上述行情链路。行情更新失败不得覆盖或删除用户会话数据。

| --- | --- | --- | --- | --- | --- | --- |

| 周末/节假日 | 国内最近结算值；境外按自身交易日 | 最近正式板块值 | 本地快照 | SQLite 历史 | 不执行当日 A 股结算 | 本地功能正常 |

### 数据源有效时间

| 数据源 | 可以发挥作用的时间 | 不能承担的职责 |
| --- | --- | --- |
| QMT HTTP `18080/ohlc_batch` | QMT 完整行情服务在线时全天可读；A 股盘中值动态，午休/盘后值固定；15:30 后目标日期校验通过可写个股结算 bar | 不负责港美股；盘中值不得写正式日线 |
| QMT HTTP `18080/candles` | 盘中提供当日分钟增量，盘后可读完整当日分钟和历史日线 | `count=-1` 不代表全部；前导零成交伪 bar 不能入库 |
| QMT 公式口 `58600` / 本地 datadir | 完整 QMT 登录后可读；15:30 后用于指数结算和诊断 | 与 18080 独立探活；58600 故障不得阻止 18080 个股结算。当前券商批量 Panel 不稳定，禁止全市场失败后逐只启动子进程；xtdata 空壳不能被误判为有效分钟源 |
| 东财 push2delay | 工作日 09:15-15:05 获取行业/概念全量盘中快照；午休使用此前缓存；盘后作候选 | 不是正式历史结算源；单页结果不是全市场 |
| Tushare `dc_index/dc_daily` | 工作日 09:15 前可读取上一结算日，17:00 后可验收当日；周末读取最近结算日 | 15:05-17:00 不用它替换东财候选；不用于板块盘中跳动和浏览器点击即时查询 |
| Tushare `index_weight` | 盘后离线维护指数成分；交互时不调用 | 不提供当前点击所需的实时价格 |
| SQLite `kline.db` | 全天、离线也可用，是图表即时首屏与结算历史真源 | 不能把未结算盘中值冒充正式数据 |
| 本地成分 JSON / SQLite 快照 | 全天可读，点击应瞬时返回 | 数据新鲜度依赖离线更新任务 |
| 腾讯/新浪全球指数接口 | 按对应境外市场交易时段变化，A 股休市时也可能继续更新 | 不可按 A 股 15:00 冻结，也不可送入 18080 |

### 09:15 前：盘前

- 历史图表读取 SQLite 最近结算数据。
- 实时接口返回的集合竞价值只能作为临时显示。
- 不写入当日日 K，不启动盘后全量任务。

### 09:15-09:30：集合竞价

- 顶部国内指数和已选标的可读 18080 临时 OHLC。
- 行业、概念板块可读东财快照。
- 所有值均为临时值，不能设置 `today_done`。

### 09:30-11:30：上午连续交易

- 当前国内个股、指数图表每 3 秒读取 18080。
- 顶部指数栏每 10 秒刷新。
- 服务端板块完整快照最多每 30 秒拉取一次。
- 数据更新调度器每 5 分钟刷新一次顶部行情内存缓存，不写 SQLite。
- SQLite 历史图负责立即绘图，实时 OHLC 只覆盖最后一根。

### 11:30-13:00：午休

- 板块冻结为上午最后一次东财快照，外部东财请求暂停。
- 18080 返回的最后值应是上午收盘值；图表不得生成 11:30-13:00 的伪分钟 bar。
- 后台 QMT 指数同步暂停，13:00 恢复。
- 午休数据仍不是正式日线，不设置完成标记。

### 13:00-15:00：下午连续交易

- 清除板块午休冻结标志。
- 当前国内标的恢复 18080 动态覆盖。
- 板块恢复东财完整快照。
- 后台顶部行情内存刷新恢复为每 5 分钟一次。

### 15:00-15:30：收盘结算缓冲

- 15:00 的 18080 最后一根分钟 bar 是下午收盘候选。
- 15:05 前允许补抓一次东财板块收盘候选。
- 不立即宣告日更完成，等待 QMT 本地日线完成落盘。
- 调度器不得在 15:30 前启动全量日更。

### 15:30-17:00：QMT 盘后增量

- 国内个股先用平安银行、药明康德、沪深300做 18080 目标日探针，至少两项命中后才启动结算；随后 `ohlc_batch` 每批 80 只写入目标日 bar。
- 单只股票只返回旧日期时，必须再用 Tushare 目标交易日全市场代码集合做一次独立核验：目标日在集合中说明 QMT 欠更，属于失败；不在集合中才可确认为停牌、退市等 `no_bar`。核验源不可用时保持待重试，禁止猜测成功。
- 国内指数通过独立探活的 QMT 公式口或本地 datadir 做增量更新；非空但日期落后的返回仍是失败，必要时 Tushare 只补指数历史尾部。
- 当日值只有在目标交易日、OHLC、行数和写入结果均通过校验后才算完成。
- 停牌、上市较晚与真实数据缺口必须区分：长时间无 bar 先记录为“可疑缺口”，不能直接判定为数据损坏。
- 板块仍使用东财收盘候选展示；此阶段 Tushare 板块日线尚不作为正式完成条件。
- 每日历史维护按 `BOARD_HISTORY_REPAIR_BATCH` 推进，默认 25 个标的；它修复长期完整性，不替代当天结算。
- 个股日更在写入前校验目标日单根 bar 的 OHLC/成交量；全市场完整历史质量由游标维护层负责，禁止每晚把 3GB 日线库完整扫描。
- 欠更判断一次读取 `kline_meta`，禁止按 5,000 多只股票逐只执行 `MAX(date)/COUNT` 查询。

### 17:00 后：正式板块结算

- Tushare `dc_index`、`dc_daily` 必须显式筛选最新 `trade_date`。
- 只有 `trade_date` 等于目标交易日时，才能替换东财候选并写入正式板块日 K。
- 禁止遍历多日返回结果后让旧日期覆盖新日期。
- 正式板块只结算分类文件中的 990 个行业/概念板块，来源覆盖率必须不低于 95%；当前 987 个有效板块成功，3 个已过期的 2025 年报主题明确记为 `unavailable`，不得算作失败或凭空造数。
- 数据未发布、数量不足或代码覆盖不完整时，每 10 分钟重试。

### 完成态

只有以下条件全部通过，才允许写 `today_done`：

1. 必要国内指数完成目标日更新。
2. 个股更新没有请求失败或硬质量错误。
3. Tushare 板块日线达到目标交易日和覆盖要求。
4. 周、月、季、年周期已从新日线原子重算。
5. 任务未取消，任何必需阶段都没有 `deferred`、`partial` 或 `skipped`。

否则状态必须保持 `pending_retry`，调度器 10 分钟后重试。

## 四、历史完整性规则

- 元数据至少包含首日、末日、行数、来源、更新时间和可疑缺口。
- 个股上市前由 18080 返回的前导零成交伪 bar 必须剔除。
- 非法 OHLC、负成交量、重复日期、空数据属于硬错误。
- QMT 的成交量可能以有符号 32 位整数返回；源端和应用端都必须把溢出的负值还原为无符号值，修复后的权威行必须稳定覆盖旧行。
- 长缺口可能是停牌，也可能是数据源漏数；没有交易日历或停复牌证据时只能标为可疑。
- 增量成功不能证明历史完整；历史修复需按可疑缺口单独核验。
- 分钟数据不落入正式日线表。
- 日线更新后，旧周/月/季/年缓存全部失效。
- 历史修复游标保存在忽略 Git 的 `data/history_repair_status.json`；默认每天处理 25 个，约 5,800 个当前标的一轮约需 232 个运行日。
- 点击图表时仍会按需检查当前标的全历史，因此常看的截断标的无需等待全市场游标轮到。
- 每日高周期重建只覆盖本次新增、修复或更正过日线的代码；首次全量重建仍可显式调用 `materialize_higher_periods()`。

## 五、调度与状态文件

- 唯一真实时间循环是 `data_update_manager._scheduler_loop`。
- `services.data_update_scheduler` 只是状态/手动触发门面，不再维护第二套时间循环。
- 调度器启动后立即判断当前交易阶段；不再并发启动第二个“启动检查”线程。
- `data/update_status.json` 是运行时状态，不进入 Git。`daily_update.status=pending_retry` 的优先级高于遗留的 `today` 字段。
- 午休手动快照也只读取 `nav_spot_service` 和冻结的 `BoardSpotCache`，不允许绕道调用 Tushare 盘中板块接口。
- 盘后任一必需阶段未通过时等待 10 分钟重试；全部通过后才进入下一交易日等待。
- 日更成功后必须通过交易日历计算“下一交易日 15:30”，禁止固定睡眠 86400 秒；周五完成后下一次应为周一（节假日继续顺延）。
- 所有 pytest 用例通过 `tests/conftest.py` 把状态文件重定向到临时目录，任何测试都不得读写生产 `data/update_status.json`。

## 六、失败降级与禁止事项

- 18080 不可用：历史图仍从 SQLite 立即显示，实时覆盖标明不可用。
- 东财快照失败：保留上一份有效快照，不返回半页数据。
- Tushare 当日未发布：保留东财候选，不写正式完成标记。
- 成分快照缺失：返回明确的 unsupported/error 状态，不把指数当概念板块查询。
- 禁止在浏览器点击过程中启动 Tushare 全量更新。
- 禁止由每个浏览器分别拉取整套东财板块。
- 禁止因外部行情失败而删除本地历史数据或用户会话数据。
